# פתרון סגירה ותצורה

ה־reload יבנה Config חדש עם generation גדול באחד, יאמת את כל השדות ורק אז יחליף Arc אחד תחת write lock. בקשה קיימת תמשיך להחזיק את ה־Arc הישן עד סיומה. המדיניות המוצעת דוחה reload בזמן Draining כדי לצמצם את מספר המצבים שהמערכת צריכה להסביר בזמן סגירה.

במרוץ admission מול drain שני המעברים נועלים את אותו gate. אם admission זוכה, הוא מגדיל active ומעביר permit לבקשה לפני שחרור הנעילה. ה־drain יראה active חי ולא יגיע ל־Stopped. אם drain זוכה, הוא משנה את השלב לפני שחרור הנעילה, ו־admission יידחה. ה־permit אינו ניתן ל־Clone, ושחרורו מתרחש רק כאשר כל פעולה שבבעלותו הסתיימה.

הבקשה שכבר התקבלה יכולה להפיק אירוע drain-retained ולחזור ל־Queued אחרי recovery אם כך הוגדר החוזה. הבקשה שטרם התקבלה מקבלת ShuttingDown או ניתוק בלי אישור קבלה. בלוג נשמור request ID לצורך תחקיר, אבל במדדי histogram נשתמש ב־labels מוגבלים כמו operation ו־status. הספירה של work-in-progress צריכה לכלול גם עבודה חוסמת שה־future שממתין לה בוטל.

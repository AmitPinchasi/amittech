# פתרון חקירה שיטתית של סדרי ביצוע

בגרסה החלשה אין קשר פרסום שמחייב את קריאת הנתון לראות את הכתיבה שהקדימה את הדגל. דוגמת הנגד צריכה להראות שהקורא ראה ready אבל עדיין קרא ערך שאינו מתאים. בגרסה התקינה, ה־acquire שרואה את ה־release יוצר את הקשר שעליו נשענת הבדיקה.

מודל תור קטן אינו חייב להשתמש באלפי פריטים כדי להיות מועיל. שניים או שלושה מעברי בעלות יכולים לחשוף שימוש חוזר מוקדם בחריץ או סגירה שאינה מעירה ממתין. נבדוק שכל פריט מתקבל לכל היותר פעם אחת ושסדר ה־FIFO נשמר עבור פעולות שהחוזה מסדר.

במדידת המנוע נשמור סכום תוצאות או מזהי משימות שהושלמו, כדי שלא לפרש אובדן עבודה כשיפור throughput. אם מספר workers גדול יותר משפר קצב אבל מחמיר זנב latency, הדוח צריך להציג את שניהם ולהסביר איזו דרישה קובעת את הבחירה.

# תרגול אמינות בין תהליכים

הרחיבו את Store כך שתוצאה שמורה תכלול גם מספר עסקה לוגי. בקשה חוזרת צריכה להחזיר את המספר המקורי, ולא לצרוך מספר חדש.

בדקו את הרצף: כתיבה ראשונה, כתיבה חדשה לאותו מפתח, replay של הראשונה וקונפליקט תוכן עם אותו מזהה. ודאו שהערך הנוכחי אינו חוזר לאחור בגלל replay.

תכננו פורמט WAL שמאפשר לשחזר את טבלת הבקשות ואת מפת הערכים יחד. ציינו את נקודת האישור ללקוח ואת מסלול הקריסה מיד לפניה ומיד אחריה.

כתבו מדיניות לסיום חלון retention. הסבירו מה הלקוח רשאי לעשות עם מזהה ישן אחרי שהחלון הסתיים, וכיצד השרת מונע פירושו בטעות כבקשה חדשה.

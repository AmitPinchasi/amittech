# תרגול קבוצת עבודה ולחץ זיכרון

הריצו את הניסוי ושמרו working set, private usage ומספר faults בכל שלב. בדקו שהתוכן נשמר אחרי trimming.

הוסיפו מדידת זמן לסריקה השנייה והשוו לכמה סריקות רצופות בלי trimming. הסבירו אילו גורמים נוספים מלבד קריאות דיסק יכולים לשנות את הזמן.

כתבו תוכנית ניסוי שמבחינה בין cache מוגבל לבין דליפה: הגדירו מספר מחזורים, תקציב צפוי ותנאי התייצבות.

נתחו מצב שבו working set יורד אך private commit אינו יורד. הציעו שתי סיבות אפשריות וציינו מה צריך לבדוק לפני בחירת תיקון.

הסבירו למה הקטנת working set באופן מחזורי אינה תיקון כללי לדליפת זיכרון.
